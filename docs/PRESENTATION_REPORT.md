# EVO SWIPE — Presentation Layer 개선 보고

## 결과

`index.html` 하나만 브라우저로 열어 실행합니다. 목업은 아트 디렉션의 기준으로만 사용했고 목업의 게임 규칙·버튼·데모 데이터를 가져오지 않았습니다.

**5회 독립 평가 완료 · 최종 93/100 · Gameplay preservation 30/30 · Hard fail 0.**

최종 HTML SHA-256: `86f4edbae14dd729ec7b6c8be8abfa7f7845ef24f3d33edd320001f8d952c026`. 회귀 검사·성능 검사·평가자의 화면 검토가 모두 이 파일을 기준으로 완료됐습니다.

## 변경한 것

- 차콜 배경, 따뜻한 종이 카드, 크림·청록·살구·민트 색상과 작은 종이 질감.
- 목업에 포함된 로고와 풍경을 HTML 안에 임베드. 기존 `icon` 클래스에 대응하는 10종 생명체 SVG와 알 수 없는 아이콘을 위한 기본 삽화.
- 시나리오 → 생명체 → 후보 환경의 시각적 순서, 데스크톱의 비조작 안내 패널, 작은 화면의 간격·타이포그래피.
- 기존 스와이프 배지의 방향 표현, 룰렛 프레임, 결과·엔딩·튜토리얼·계통도·수업 도구의 표면과 버튼.
- 작은 화면의 안내 줄바꿈, 버튼 접근성 이름, 모달 내부 스크롤, 배경 스크롤과 카드 퇴장 영역의 시각적 제한.
- 외부 Tailwind 런타임·Font Awesome·Pretendard 요청을 내장 CSS·SVG·시스템 글꼴로 대체. 새 JavaScript를 추가하지 않았습니다.

## 변경하지 않은 것

게임 스크립트 **46,376바이트 전체가 원본과 동일**합니다.

`SHA-256: 9c3811e53c153c817b7398d8bdf26b62053e8b17adb402fcdc4149c1c0d72107`

- 10개 진행 노드, 15개 환경, 17개 엔딩, 60개 페이오프, 32개 갈래의 데이터·순서·선택 내용.
- RNG/seed, 한 턴의 이벤트 순서, 개체군 계산, 번성·생존·멸종, 엔딩·체크포인트, 발견·플레이 기록.
- 스와이프 12/60/80px 규칙, 퇴장 후 260ms 처리, 룰렛 2.5초와 결과 표시 시점, 기존 키보드·터치 입력.
- 71개 기존 ID와 요소 종류, 모든 data-step 및 동적 DOM 참조.
- 현재 index의 메모리 기반 상태. 원래 없던 저장 기능을 추가하지 않았습니다. localStorage를 쓰는 별도의 구버전 `evolution_swipe.html`도 파일 전체를 그대로 보존했습니다.

삽화는 게임의 노드 ID나 종 이름으로 분기하지 않고 기존 아이콘 클래스만 따라갑니다. 제목·시대·선택지·환경·결과는 원본 렌더러가 계속 출력합니다. 알 수 없는 아이콘도 기본 삽화로 표시됩니다.

### 반복 성능 비교

1280×900 Headless Chromium에서 원본의 실제 CDN 응답 9개를 캐시로 재생해 정상 스타일·아이콘·글꼴을 적용했습니다. 원본/개선본 각각 CPU 1배·4배 제한에서 5회씩, 총 20회 실행했습니다. 라이브 네트워크와 다른 캡처 작업은 제외했습니다. 다음은 각 그룹의 중앙값입니다.

| 측정 항목 | 원본 1배 | 개선본 1배 | 원본 4배 | 개선본 4배 |
|---|---:|---:|---:|---:|
| 화면 준비 | 1,767ms | 315ms | 4,612ms | 1,382ms |
| 룰렛 안정 구간 프레임 간격 p95 | 116.7ms | 16.8ms | 133.4ms | 16.8ms |
| 스와이프 프레임 간격 p95 | 33.4ms | 16.8ms | 33.4ms | 16.7ms |
| 첫 결과창 프레임 콜백 | 83.5ms | 56.4ms | 257.8ms | 277.7ms |

로딩과 지속적인 조작·회전은 개선됐습니다. 4배 제한에서 첫 결과창의 프레임 콜백은 약 20ms 느렸으며, 첫 구간 최대 long task의 중앙값도 238→277ms였습니다. 이 일회성 비용을 포함해 기록했습니다. CPU 제한은 이 컴퓨터의 시뮬레이션이며 모든 저사양 기기에서의 실측을 뜻하지 않습니다. 20회 모두 JS 오류와 누락 리소스는 0이었고 최종 파일 해시도 유지됐습니다. 원자료: [performance-final.json](../qa/performance-final.json).

4배 제한의 개선본 5회 중 한 번은 룰렛 p95 33.3ms·최대 183.3ms였고, 다른 한 번은 후반에 59ms 작업이 기록됐습니다. 따라서 위 중앙값을 모든 프레임이 항상 60fps라는 뜻으로 해석하지 않습니다. 독립 평가자는 전체 로딩·조작 개선과 이러한 한계를 함께 검토해 성능 14/15점을 부여했습니다.
